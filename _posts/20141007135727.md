フォーム内の未入力のInputなどのパラメータを精査する。

jQueryを使わない方法は、「[[JavaScript] 空のGETパラメータを送信しない方法](https://b.0218.jp/20170409220848.html)」を参照。

<!--more-->

少し前に「[[PHP] GET で渡された空白パラメータを削除する方法](https://b.0218.jp/20140930104851.html)」という記事を書いた。
これはサーバサイドで`GET`の値を直接操作する方法で個人的にあまりやりたくない方法だった。

そこでも書いているけれど、そもそも**フロント側で空のパラメータは送信しなければ良い**のではないかと考えていた。

## 方法

サブミット時に空のパラメータだけ削除して送信する。

### jQueryプラグイン

結果として、軽く調べるとjQueryプラグインがあったので大人しくそれを使うことにする。

[jQuery cleanQuery（Wayback Machine）](https://web.archive.org/web/20201030151043/https://github.com/guimihanui/jQuery-cleanQuery)

```js
$('form').cleanQuery();
```

使い方は、上記のように指定のフォームに対してcleanQuery()をあてがうだけ。

詳しい解説は[HTML - 値が空のパラメータがクエリー文字列に入らない GET のフォーム - Qiita（Wayback Machine）](https://web.archive.org/web/20211117043255/https://qiita.com/guimihanui/items/1aeab53b3776ebec97ab)にあったので引用しておく。

内部的には、サブミット時に以下の流れで処理をしている。

1. サブミットを中止
2. フォーム内のパラメータを取得
   - 取得したパラメータから値が空のものを取り除く
3. 正規化したパラメータをフォームのactionにくっ付けて遷移させる（GET）

```javascript
/*
 * jQuery cleanQuery 2013-03-23
 * Authored by guimihanui
 * Licensed under the MIT License (http://www.opensource.org/licenses/mit-license.php)
 */

(function ($) {
  function cleanQuery(query) {
    var arr = [];
    $.each(query.split('&'), function (i, param) {
      if (param.split('=')[1]) {
        arr.push(param);
      }
    });
    return arr.join('&');
  }

  $.fn.cleanQuery = function () {
    this.on('submit', function (event) {
      event.preventDefault();

      var query = cleanQuery($(this).serialize());
      location.href = this.action + '?' + query;
    });

    return this;
  };
})(jQuery);
```

### 改変

途中まで自分の作っていたコードもあったのだけれど、こちらのコードをベースに要件へ沿う形で改変させてもらった。（フォームを弄る別のソースと混ぜ込む形で使いたかったのでプラグインから切り離した）

```javascript
$('.clean-query').on('submit', function (e) {
  e.preventDefault();

  var query = $(this).serialize();
  // 文字列の連結ではなく、URLのqueryを差し替える。連結はactionにqueryやfragmentがあるとURLが壊れるため
  var url = new URL(this.action);

  url.search = (function () {
    var arr = [];
    $.each(query.split('&'), function (i, p) {
      if (p.split('=')[1]) {
        arr.push(p);
      }
    });
    return arr.join('&');
  })();

  location.href = url.href;
});
```

空のパラメータを取り除く処理は全く同じだけど、ここでしか使われない`cleanQuery()`を新たに記述するのもアレだったのでクロージャしている。URLの組み立てだけは`URL`オブジェクトに変えている。

普通に使うのであれば大人しくプラグインを使った方が良いだろう。

## 注意点

<details>
<summary>URLが崩れるケースと、改変したコードに残る制約</summary>

ブラウザ本来のGET送信は`action`のクエリを差し替えるが、プラグインは`this.action + '?' + query`で文字列を連結するため、次のケースでURLが意図どおりにならない。

- `action`にクエリがある（`/search?lang=ja`）と`?`が重複し、URLが壊れる（`/search?lang=ja?q=foo`）
- `action`にフラグメントがある（`/search#top`）と、クエリがフラグメントに含まれてサーバへ届かない（`/search#top?q=foo`）
- URLにクエリがあるページ（`/search?a=1`）で、`action`属性がない（または空の）フォームを送信すると`?`が重複する（`/search?a=1?q=foo`）
- 値がすべて空だと、URLの末尾に`?`が残る（`/search?`）

改変したコードは`URL`オブジェクトでクエリを差し替えるため、この4点は発生しない。ただし、`URL`はIEが非対応である。

次の2点は改変したコードでも残る。

- 送信ボタンに`name`を指定しても、値は[`serialize()`](https://api.jquery.com/serialize/)に含まれないため送信されない
- 空白だけの値は空として扱われず、送信される

</details>
