# Article Foundation Editor

記事タイプを問わず、公開前の記事として破綻しない土台を整える。技術記事の再現性や詳細な事実調査は扱わない。

範囲外:

- 技術記事の再現性検証。`tech-article-reproducibility` を使う
- 外部一次資料の詳細調査
- 誤字修正だけで完結する依頼。このスキルを通さず直接修正してよい

## 絶対制約

CLAUDE.md の絶対制約と執筆ルールに従う。

- `textlint-disable` / `textlint-enable` コメントは削除・移動しない(範囲内の本文は編集してよい)。変更が必要なら変更案として報告する。
- `AI編集禁止` の終了位置が判断できない場合は、該当箇所を編集せず報告する。
- ユーザーの体験談、感想、言い切りの強さを勝手に中和しない。
- 記事タイプの変更、段落の大幅削除、体験談の削減は、ユーザーが明示した場合だけ行う。

## ワークフロー

依頼が「レビュー」「提案」「dry-run」の場合はファイルを編集しない。編集を依頼された場合だけ、保護範囲を避けてファイルを変更する。

1. フロントマター、`textlint` コメント、`AI編集禁止` 範囲を確認する
2. `title` / `tags` と本文冒頭から記事タイプを判定する
3. 記事タイプ別の観点で、必要最小限の補正を行う
4. 編集した場合は CLAUDE.md『品質検証』のコマンドをエラーゼロまで実行する。`markdown-link-check` は公開前の最終確認を依頼された場合だけ実行する
5. 実行できない検証は未実行理由を報告する。報告には判定した記事タイプと、保護範囲・textlint コメントへの変更提案(あれば)を含める

## 記事タイプ判定

まずフロントマターの `title` / `tags` で早期判定し、見出しと本文冒頭で確認する。迷ったら複数タグの混合として扱い、強い変換を避ける。

技術記事は article-types.md の問題解決型・調査・比較型・知識共有型・設計論型に対応し、以下の雑記・感想・レビュー・イベント記録・短いメモは article-types.md の「その他」の内訳である。

| タイプ         | 判定材料                                                                                                          | 主な編集方針                                                                                                           |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 技術記事       | `tags` に言語・ライブラリ・ツール名がある、タイトルが `[技術名] ...` 形式、コード、コマンド、実装手順、エラー対処 | 事実・手順・前提を明確にする。再現性の深掘りは別スキルに渡す                                                           |
| 雑記           | 個人的な考え、近況、ゆるい記録                                                                                    | 主題と話題の流れを整える。個人の声を残し、結論を無理に教訓化しない                                                     |
| 感想・レビュー | 作品、イベント、製品、体験への評価                                                                                | 事実情報と主観を分ける。評価は「自分にとって」の範囲に保ち、ネタバレ・価格・開催日など読者判断に影響する前提を明示する |
| イベント記録   | 日時、会場、プログラム、参加体験                                                                                  | 記録情報を整理し、感想と混ざりすぎないようにする                                                                       |
| 短いメモ       | 小さな発見、解決ログ、覚え書き                                                                                    | 結論、背景、再利用できる情報を明確にする                                                                               |
